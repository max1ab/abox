Claude Code for some things, Codex for others, Cursor when I want the editor, Grok when I want a second opinion. The work moves between them all the time, but the context doesn't. Every switch meant opening a new window and explaining the same branch, the same failing test and the same constraint I had already explained once. The frustrating part is that the context is already on my disk. Each of these tools writes its session transcript somewhere under my home directory. Nothing reads across them. So I wrote magents: a Rust MCP server plus a small CLI that is a shared API over those sessions. It is not a second copy of history and it is not a "council of agents". Your existing chats stay the unit of work. magents just lets them see and reach each other. It supports Claude Code, Codex, Copilot CLI, Cursor, Gemini CLI, Grok and OpenCode. Inside any of them you get roughly four moves. Read another session. list_sessions, session_digest and read_transcript let the agent you're in see what another one was doing: the last request, the last action, the working directory and the branch. I can sit in Grok and ask "what was Claude doing on the disaster-recovery branch? ", and it reads the live session and carries on. Send into a specific chat. send_message delivers a user turn into an existing session. That's useful when one agent hits a wall that another agent's session already owns, because the sender already has the failing query and the file in hand. I don't have to be the messenger. Hand off. handoff compacts the current session and injects it into another live one, so that session continues the same work. Spawn independent work. spawn_session starts a new headless, persisted session with a complete task, an optional isolated working directory, and a request to reply through magents. Spawned sessions keep their host's own approval policy. magents never adds flags like --dangerously-skip-permissions, --yolo or --full-auto. Replies come back through a small mailbox (inbox, ack, await_reply, reply) stored under magents' own directory. A spawned Codex session can report back to the Claude session that started it. One rule matters a lot here. Transcripts from other agents are treated as inert, untrusted history. The agent reads them as data, not as instructions to follow. magents doesn't keep its own index. It reads each host's own files when you ask: Claude: ~/.claude/sessions Codex: its SQLite state plus rollout JSONL Cursor: agent-transcripts OpenCode: its SQLite database Gemini CLI: its journals Copilot CLI: session-state Grok: ~/.grok/active_sessions.json A few details from the Rust side: SQLite. rusqlite opens the host databases with SQLITE_OPEN_READ_ONLY, so a running agent never competes with magents for a write lock. Delivery into existing chats. magents always records the message in its mailbox first, then uses the most direct path the host has. That's a Unix-socket user turn for Claude, length-prefixed JSON-RPC on Codex Desktop's IPC socket, and otherwise a supervised headless resume of that exact session (codex exec … resume, cursor-agent --resume, gemini --resume, and so on). The user turn goes over stdin, never as a process argument. Supervisor. It is plain tokio::process with each child in its own process group (setpgid/setsid in pre_exec), so stopping a session signals the whole group rather than one PID. Format drift.
